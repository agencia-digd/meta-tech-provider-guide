# Revisão de 24/09/2026 — fontes e pontos não confirmados

## Escopo e método

Li integralmente o README original de 25/06/2026 e revisei o conteúdo contra
páginas oficiais consultadas em 24/09/2026. Trabalhei somente em `/tmp/mtpg`.
Não acessei painel autenticado, app ou conta de cliente; não fiz submissões,
commit ou push. As alterações são documentais, não uma certificação de um app.

A busca web por Tech Provider, App Review e preços no domínio oficial não
retornou resultados. A abertura de algumas páginas pela ferramenta web falhou
com HTTP 429 ou indisponibilidade. A consulta HTTP direta pela VPS funcionou:
várias URLs antigas redirecionam para `/documentation/`, com conteúdo Markdown;
as referências de níveis de acesso e Insights foram lidas em HTML, removendo
scripts e estilos. As fontes abaixo foram efetivamente lidas, salvo as
explicitamente marcadas como indisponíveis.

Não foi possível estabelecer a data de mudança de cada regra comparando versões
arquivadas. “Corrigido” significa divergência entre o README e a documentação
consultada, não necessariamente alteração da Meta posterior a 25/06/2026.

## O que não foi confirmado

Os relatos abaixo foram preservados e identificados no README, como solicitado:

- **Não confirmado:** domínio verificado obrigatoriamente na mesma BM como
  condição universal para destravar Advanced. As páginas de [Business
  Verification](https://developers.facebook.com/documentation/development/release/business-verification)
  e [Tech Provider](https://developers.facebook.com/documentation/business-messaging/whatsapp/solution-providers/get-started-for-tech-providers)
  confirmam o vínculo app–empresa, mas não sustentam essa generalização sobre domínio.
- **Não confirmado:** correspondência atual de `131030` com allow-list, incluindo
  os passos/check verde descritos. O código não apareceu na referência de
  [erros](https://developers.facebook.com/documentation/business-messaging/whatsapp/support/error-codes)
  consultada; o [Get Started](https://developers.facebook.com/documentation/business-messaging/whatsapp/get-started)
  não confirmou esse procedimento específico.
- **Não confirmado:** associação determinística dos erros Instagram `#-2` e
  `2534084` à ausência de Tester; nem que adicionar Tester sempre resolva.
- **Não confirmado:** requisito exclusivo de Page Token para `leadgen_forms`.
  A fonte de [recuperação de leads](https://developers.facebook.com/documentation/ads-commerce/marketing-api/guides/lead-ads/retrieving)
  trata vários cenários e não basta para validar a exclusividade naquele endpoint.
- **Não confirmado:** timeout de 60 segundos com uma repetição como solução de
  `conversations`. Mantido como ajuste empírico do autor.
- **Não confirmado:** disponibilidade e uso de `instagram_manage_contents`, nem
  as 15 aprovações históricas. Não houve acesso a um app para validar o relato.
- **Não confirmado:** referência específica de `pages_read_user_content` e a
  orientação histórica associada. A URL consultada retornou 404; o relato foi
  mantido como não confirmado, sem instruir descarte universal de permissões.
- **Não confirmado:** prazo numérico de Business Verification e duração real de
  ponta a ponta. A documentação de desenvolvimento não dá esse prazo; a página
  de ajuda tentada não apresentou conteúdo útil. A estimativa original de
  “~5 dias úteis” permanece mencionada como relato, não como regra atual.
